# Strategy

- Rubric: quality 60% (weighted rating of the valid answers over each request's best legal free rating), served 15%, wire 10% (shape + streaming checks), failover 10%, catalog 5%; tie-break = fewer provider calls, then earlier receipt.
- Dev board state: 3,992 entries tied at score 99 (the cap: 0.6*99 quality + 40 = 99.4), 119 of them at the (99, 20-calls) optimum; tie-break = fewer calls then EARLIER receipt, so the dev podium is structurally locked to earlier entries. The win condition is the FINAL on hidden instances, where only entries that reproduce (99, ~20) there rank. Quality 100 is unreachable on any instance (17 of 20 requests peak on one provider whose free-tier budget and refusal schedule can never cover them), so the real contest is quality 99 with the fewest upstream calls.
- Generalization guarantees: the catalog is probed from each provider's own route in its own auth scheme (never the brief alone), so it matches whatever the final instance lists; capabilities, ratings and the per-request quality bound come from the brief; nothing is hardcoded from the practice trials. The hidden per-trial inputs (budgets, refusal schedules, the outage, the designated second-call refusal) cannot be derived at trial time - the harness hands the entry a stand-in trial seed, not the instance seed - so the router runs on priors plus observation instead: each provider's refusal risk is modeled from the sealed tier bounds (fail numbers land in [2, budget-1], so a first call is always safe while depth on a narrow-window provider is risky; one provider of ten refuses its second call; one goes out mid-trial; a refused call still consumes its call number). Every request takes the candidate minimizing expected attempts plus a quality-loss term, subject to a weighted-loss budget that keeps the quality column at its cap (the budget reserves the cheapest possible loss of every remaining request and tightens as it fills), and re-ranks after every refusal using what the provider's own message revealed ("budget is spent" / "is out" kill a provider, "refused this call" burns one of at most two scheduled numbers).
- Wires: requests are translated between OpenAI, Anthropic and Gemini wires (system, tools + tool_choice, images, JSON mode - only onto wires that carry it, max_tokens, stops, stream) so the provider's echo matches the client byte for byte; provider calls are made non-streaming and client SSE (event order, [DONE]/message_stop, usage placement, stop-reason families) is synthesized from the provider's answer with its exact usage counts. Zero wall clock, zero randomness, one provider call at a time, manifest order - the trial replays byte for byte.
- Run it: `node main.ts` inside a trial (Node 22, stdlib only); `node main.ts --list` prints the catalog document byte for byte as registered, `{"providers":[]}` with no brief.
